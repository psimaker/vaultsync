# 058 — A share never syncs into the selected folder itself

**Context.** A share's local directory was `root/<name>`, with two shortcuts into the root: when the label matched the root's name on disk (1.0.2, against `Obsidian/obsidian`), and when the root held a `.obsidian/` and no vault subfolder (a single vault picked as root). Read on a device and on the iOS 18 and 26 simulators (#270): the picker returns Obsidian's folder as `…/Containers/Data/Application/<UUID>/Documents` — its name on disk is `Documents`, never `Obsidian` — and Obsidian lists the direct subfolders of its folder as vaults, nothing else. So the first shortcut fired for a vault labelled "Documents" and inside folders users had made and named "Obsidian"; the second for a `.obsidian/` left behind in Obsidian's folder. Either way the vault arrived in full and never appeared in Obsidian.

**Decision.** The selected folder is a container, always. `resolveSharePath` returns `root/<name>` (or its numeric-suffix variant) or nothing. A root that is itself a vault (`rootIsItselfVault`, 014) refuses a label-derived accept with the guidance to select the folder that contains the vaults. An app's own folder (`isAppDocumentsRoot`: `…/Application/<UUID>/Documents`, or the app's folder in iCloud Drive) is a container whatever it holds. The folder names `.` and `..` are refused. The Go floor holds the same line: `AcceptPendingFolder` takes the selected folder and accepts only into a direct subfolder of it. Nothing that already syncs is moved or re-pointed (002, 003): a folder syncing into the root keeps doing so. A recorded manual target (#52, 006) keeps its place, whatever the share is labelled now (its consent to a directory that holds files counts only under the selected folder it was chosen in, 060); a new manual choice under a root that is itself a vault is refused like a label-derived one.

**Why.** Obsidian decides what a vault is; a place it does not list is a failure that looks like success, because the file count rises. A refusal with the way out costs one re-selection; a collapse costs the user a vault they cannot find. One level, enforced in two layers (001), is a rule no label can argue its way around.

**Rejected alternatives.** Keeping the collapse for a single vault picked as root, the one case where the old shortcut worked: the mapping would go on depending on what the root happens to hold when a share arrives — the misclassification behind #79. Recognizing Obsidian's folder by name: on disk it is `Documents` for every app, and `localizedName` and `FileManager.displayName` say `Documents` too. A Go floor without the selected folder, comparing against configured folders only: it cannot tell the root from its child.
