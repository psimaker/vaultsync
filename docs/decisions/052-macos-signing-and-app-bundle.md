# 052 — VaultSync for Mac is signed and notarized on a Linux runner; the tray ships as VaultSync.app

**Context.** M4 step 3 (#176, #222). The macOS binaries carried the Go linker's ad-hoc signature (identifier `a.out`), which changes with every build: macOS asked again for Documents access after each update, and Gatekeeper killed a copy a browser had downloaded. The tray had no bundle, so it could not be a menu-bar-only app, and its cgo build targeted the build runner's own macOS.

**Decision.** (1) `desktop-release.yml` signs with the owner's Developer ID Application certificate and notarizes with `rcodesign` (pinned by version and SHA-256) on an Ubuntu runner, in the one job that sees the secrets: environment `desktop-signing`, reachable by `desktop-v*` tags only; that job checks out nothing and signs this run's artifacts. `--for-notarization` enforces the Developer ID, the secure timestamp and the hardened runtime on every Mach-O. A macOS job then checks the result with Apple's own tools (`codesign --strict`, `--check-notarization`, `stapler validate`, `spctl`) before the release job publishes; the release takes macOS binaries only from the signed artifact. (2) The agent signs as `eu.vaultsync.agent` wherever it ships — as the bare `vaultsync_darwin_<arch>` that setup.sh installs (its copy in VaultSync's folder keeps the bytes, so the signature) and inside the bundle: identifier plus team is the designated requirement macOS ties a permission to, so a grant survives updates. (3) `VaultSync.app` (`eu.vaultsync.desktop`, LSUIElement, LSMinimumSystemVersion 12.0) has the tray as its executable and the agent beside it in `Contents/MacOS`; one bundle per architecture, `VaultSync_darwin_<arch>.zip`, stapled. The bare macOS tray is no longer published. The tray's cgo build pins `-mmacosx-version-min` through `CGO_CFLAGS`/`CGO_LDFLAGS` (part of Go's cache key; `MACOSX_DEPLOYMENT_TARGET` is not), and the build fails when a binary's minos differs from the plist. (4) A tag with a suffix makes a draft release: a full signing run that setup.sh never sees.

**Why.** The owner's plan (#176): rcodesign on Linux keeps the secrets off a macOS image with a login keychain and needs no keychain juggling; Apple's tools still have the last word, on what actually ships. A stable designated requirement is the whole point of #222; bundling gives the tray a real app identity without changing how the agent is installed today.

**Rejected alternatives.** `codesign` + `notarytool` on the macOS runner (a temporary keychain holding the private key on a shared image, and `security` state to clean up; Apple tooling is used for checking instead). A universal bundle (lipo needs macOS for the agent too, and the setup link already picks the architecture). Keeping a bare `vaultsync-tray_darwin_<arch>` (it was never released; outside a bundle it is not a menu-bar-only app). Stapling the bare agents (a Mach-O cannot hold a ticket; Gatekeeper looks it up online).
