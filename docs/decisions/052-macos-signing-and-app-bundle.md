# 052 — VaultSync for Mac is signed and notarized on a Linux runner; the tray ships as VaultSync.app

**Context.** M4 step 3 (#176, #222). The macOS binaries carried the Go linker's ad-hoc signature (identifier `a.out`), which changes with every build: macOS asked again for Documents access after each update, and Gatekeeper killed a copy a browser had downloaded. The tray had no bundle, so it could not be a menu-bar-only app, and its cgo build targeted the build runner's own macOS.

**Decision.** (1) `desktop/macos/sign.sh` signs with the owner's Developer ID Application certificate and notarizes with `rcodesign` (pinned by version and SHA-256 in `install-rcodesign.sh`) on an Ubuntu runner, in the one job that sees the secrets: environment `desktop-signing`, reachable by `desktop-v*` tags only (a `.p12` in the legacy PKCS#12 format rcodesign reads). `--for-notarization` enforces the Developer ID, the secure timestamp and the hardened runtime on every Mach-O; every rcodesign call runs with `-C /dev/null` and a cleared environment, so no `rcodesign.toml` and no `rcodesign_*` variable (rcodesign reads them in any case) changes what is signed, and no `RUST_LOG` what it prints. The certificate's team is checked against `MACOS_TEAM_ID` before anything is signed; every step that talks to Apple (time stamps, uploads, waits, staples) is retried. The two bundles go up once each and are waited for with retries (a network error ends a wait, not the notarization); the verdict comes from rcodesign's last poll line, since `notary-wait` exits 0 either way; stapling is retried. The bare agent is the bundled one's bytes signed the same way — one code directory — so the bundle's ticket covers it. `desktop/macos/verify.sh` then checks the result on a Mac with Apple's own tools (`codesign --strict`, no entitlements, only system libraries, the designated requirement against the team in the repository variable `MACOS_TEAM_ID`, the shared code directory, `--check-notarization`, `stapler validate`, `spctl`, both programs start) before the release job publishes; the release takes macOS binaries only from the signed artifact. Every pull request runs the same scripts ad hoc and `sign.sh`'s release path against a stand-in for rcodesign's Apple calls, every flag checked against the pinned binary (`tests/sign-release-test.sh`, its own job, no build needed); the real Developer ID and Apple's verdict first meet a tag, which is why a `desktop-vX.Y.Z-rc` draft comes before every release. The gate is the tag: whoever can push a `desktop-v*` tag runs the tagged commit's scripts with the secrets — required reviewers on the environment or a tag ruleset narrow that further. A release is all or nothing, so an Apple-side failure holds the Linux binaries back too, and a tag moved during the run is not published. No variable named `RCODESIGN_*` may be set around rcodesign: it reads each as configuration and refuses unknown keys. (2) The agent signs as `eu.vaultsync.agent` wherever it ships — as the bare `vaultsync_darwin_<arch>` that setup.sh installs (its copy in VaultSync's folder keeps the bytes, so the signature) and inside the bundle: identifier plus team is the designated requirement macOS ties a permission to, so a grant survives updates. (3) `VaultSync.app` (`eu.vaultsync.desktop`, LSUIElement, LSMinimumSystemVersion 12.0) has the tray as its executable and the agent beside it in `Contents/MacOS`; one bundle per architecture, `VaultSync_darwin_<arch>.zip`, stapled. The bare macOS tray is no longer published. The tray's cgo build pins `-mmacosx-version-min` through `CGO_CFLAGS`/`CGO_LDFLAGS` (part of Go's cache key; `MACOSX_DEPLOYMENT_TARGET` is not), and the build fails when a binary's minos differs from the plist. (4) A tag with a suffix makes a draft release: a full signing run that setup.sh never sees; any tag other than `desktop-vX.Y.Z` or `desktop-vX.Y.Z-<suffix>` stops the run before anything is built. (5) Until the LaunchAgent names the bundle (`AssociatedBundleIdentifiers`, M4 step 3 part 2), macOS lists the signed background service under the certificate's name, the developer's; the bundle's `NSLocalNetworkUsageDescription` serves the agent once it runs from the bundle.

**Why.** The owner's plan (#176): rcodesign on Linux keeps the secrets off a macOS image with a login keychain and needs no keychain juggling; Apple's tools still have the last word, on what actually ships. A stable designated requirement is the whole point of #222; bundling gives the tray a real app identity without changing how the agent is installed today.

**Rejected alternatives.** `codesign` + `notarytool` on the macOS runner (a temporary keychain holding the private key on a shared image, and `security` state to clean up; Apple tooling is used for checking instead). A universal bundle (lipo needs macOS for the agent too, and the setup link already picks the architecture). Keeping a bare `vaultsync-tray_darwin_<arch>` (it was never released; outside a bundle it is not a menu-bar-only app). Stapling the bare agents (a Mach-O cannot hold a ticket; Gatekeeper looks it up online). Repository secrets, as 048 first had it (every branch's workflow could read the Developer ID key). Signing only on tags with an ad-hoc `codesign` check on pull requests (an rcodesign-side defect would first show at a public tag).
