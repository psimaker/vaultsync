# 044 — Fresh design: one token set, status-first pages, one status per vault

**Context.** #187 implements the canvas the owner approved on 2026-09-14 (Direction A, "calm, status-first"). The app mixed system `List` chrome with hand-built cards, derived a vault's state ad hoc in `ContentView` (a paused folder read "Unknown", a missing folder "Error"), and the brand teal and the status colors fell to 3.7–4.3:1 when used as 15–17 pt text — on white and on their own washes.

**Decision.** Screens are built from the Theme tokens and the `DesignSystem` kit — `VaultPage`, `StatusHeroCard`, `VaultCardGroup`/`VaultRow`, `StatusChip`, `VaultButtonStyle` — while navigation chrome (large titles, toolbars, tab bar, alerts) stays the system's. A tone (`VaultTone`) always pairs a wash with its text color: text uses `vaultAccentText` and the `status…Text` tokens, never the brand or status color itself (≥ 4.8:1 on every wash; Increase Contrast goes further). A vault's status comes only from `VaultStatusModel`, whose precedence mirrors the header cascade of decision 012 (missing folder → paused → error → transfer → conflicts → waiting for first sync → up to date → unknown), and only the two engine states the header counts as a transfer render as "Syncing". Established section names stay — Sync Issues, Pending Shares, Obsidian Vaults — because docs, store copy and remediation text point at them.

**Why.** One token set and one kit keep the next screen consistent without re-deciding colors; one status model per vault keeps a row, its detail screen and the header from contradicting each other — the lie-class of #61/#66 at vault level.

**Rejected alternatives.** Custom-drawn tab and navigation bars (fights Liquid Glass on iOS 26, diverges on iOS 18). Restyling system `List` sections (no control over the 16/28 radii, hairlines or tinted cards, and iOS 26 changes their geometry). Inline previews for every conflict in the list (one bounded bridge read per conflict on open, decision 041; the list stays a list, the diff screen carries the canvas card). Settings as a pushed screen (checklist remediations run from the sheet's `onDismiss`). Pending shares on the Devices tab (splits the accept decision from the vault list and its consent alerts, decisions 007/011). Mapping `sync-preparing`/`scan-waiting` to "Syncing" (a row would say "Syncing" under an "All Synced" header).
