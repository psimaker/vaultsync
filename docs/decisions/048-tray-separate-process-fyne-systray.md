# 048 — The tray is a separate process on fyne.io/systray; the agent stays headless and pure Go

**Context.** M4 (#176): a menu-bar/tray icon for the desktop agent (status, pause/resume, open a vault, pair) and installation through Homebrew, Flatpak and winget. The agent `vaultsync` (046) is cross-compiled with CGO_ENABLED=0 on a Linux runner for all four platforms and runs as a LaunchAgent / systemd user service. macOS ties the Local Network and Files & Folders grants to the signed identity, and today every release of the unsigned binary is a different program (#222).

**Decision.** (1) The tray is its own binary, `vaultsync-tray`, on `fyne.io/systray` (v1.12.x: Cocoa through cgo on macOS, StatusNotifierItem over DBus in pure Go on Linux and BSD, Win32 on Windows). It never touches Syncthing and decides nothing: it asks the agent over a local control socket in the state directory — status, pause/resume, open, start pairing — and shows exactly what `vaultsync status` shows. The agent stays pure Go and cross-compiled as today. (2) macOS ships as `VaultSync.app` (LSUIElement) holding both binaries, signed with the owner's Developer ID Application certificate and the hardened runtime and notarized from the Linux release runner with rcodesign (certificate and App Store Connect key as repository secrets); the LaunchAgent points into the bundle, so the code identity and the grants survive updates (#222). A Homebrew cask in `psimaker/homebrew-vaultsync` installs it; the setup link installs the bare agent until the cask exists, then the app. (3) Linux ships as a Flatpak on Flathub with `--filesystem=home`, `/media`, `/mnt`, `/run/media` and `--share=network` — the permissions Obsidian's own Flatpak asks for; inside the sandbox the tray starts at login through the Background portal and supervises the agent as its child, while the tarball install keeps the systemd user unit. On GNOME without a StatusNotifierWatcher the tray names the extension to install, once. (4) Windows follows the agent's service model there (a Scheduled Task): a winget manifest with a hash-pinned portable zip, unsigned by decision (winget-pkgs accepts it; a certificate can come later).

**Why.** A cgo dependency inside the agent would end cross-compilation and drag Cocoa into the service; a second process keeps the service small and the tray replaceable. fyne.io/systray is maintained, small and dependency-free on Linux. A notarized bundle is the only way macOS keeps a permission across versions. Flatpak is where Linux users look first, and the sandbox permissions a sync tool needs are the ones Obsidian itself ships with.

**Rejected alternatives.** Wails v3 (still beta, a WebView for a status menu). The full Fyne toolkit (OpenGL, heavy in a Flatpak). Tauri or a native Swift menu-bar app (a second language and toolchain for a menu; revisit only if systray's macOS fidelity proves insufficient). getlantern/systray (GTK, unmaintained). The tray inside the agent binary (cgo everywhere, no cross-compilation). Signing on a macOS runner (slower, nothing rcodesign cannot do).
