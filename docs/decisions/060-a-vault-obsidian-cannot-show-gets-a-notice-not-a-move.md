# 060 — A vault Obsidian cannot show gets a notice, never a move

**Context.** 058 and 059 keep a new vault out of the two places Obsidian does not list (#270): the selected folder itself, and a folder that is no app's own. Installs set up before them can already be there, and they look healthy: the file count is right, the status says synced. Read in the code: a connected install had no way to open the folder picker — it is offered only once access is lost — so "select Obsidian's folder" was a step nobody could take.

**Decision.** `ObsidianVisibility` reports two findings, on settled paths (008), as warning-tier entries of the issue list (012). *A vault in the selected folder itself*: a folder whose path is the selected folder, where that folder is an app's own folder (`isAppDocumentsRoot`, 058) and by content a single vault — a `.obsidian/` of its own and no vault subfolder (the rule of 014). *A selected folder outside every app's own folder* (`selectedFolderPlace == .elsewhere`, 059), also while nothing syncs there, because the next share would land in it. Nothing is paused, moved or re-pointed (002, 003): the notice gives the manual way out — remove the vault, select Obsidian's folder (the notice carries the button), accept the share again. "Keep It This Way" records the choice per vault or per selected folder, and the notice stays away; removing the vault forgets its record. A pending share shows the destination its accept would choose (`previewShareDestination`) and says so when Obsidian cannot show it.

**Why.** Moving a synced folder is how a vault gets attached to the wrong content (003). A notice costs nothing and ends a setup that only looks finished. Without a way to put it away, an install that syncs elsewhere on purpose would read "Action Needed" for good.

**Rejected alternatives.** Reporting every folder that syncs into the selected folder: a whole-directory sync whose shared folder contains the vaults looks the same by path and is shown by Obsidian. Reporting when a `.obsidian/` lies next to vault subfolders: 014 found that a stray one is common there, so a vault collapsed next to other vaults stays unreported. A critical issue or a pause: nothing is being damaged. Moving the vault for the user: 002.
