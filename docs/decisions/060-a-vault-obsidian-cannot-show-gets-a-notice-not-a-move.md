# 060 — A vault Obsidian cannot show gets a notice, never a move

**Context.** 058 and 059 keep a new vault out of the places Obsidian does not list (#270): the selected folder itself, and a folder that is not an app's own. Installs set up before them can already be there, and they look healthy: the file count is right, the status says synced. Read in the code: a connected install had no way to open the folder picker — it is offered only once access is lost — so "select Obsidian's folder" was a step nobody could take.

**Decision.** `ObsidianVisibility` reports two findings, on settled paths (008), as warning-tier entries of the issue list (012). *A vault in the selected folder itself*: a folder whose path is the selected folder, where that folder is an app's own folder (`isAppDocumentsRoot`, 058) and by content a single vault — a `.obsidian/` of its own and no vault subfolder (the rule of 014); once reported it stays reported until the vault is removed or kept, because the content changes when the user opens one of its folders in Obsidian. *A selected folder that is not an app's own folder*: outside every app's folder, or inside one unless it is the single vault that syncs there. Nothing is paused, moved or re-pointed (002, 003): the notice gives the manual way out — remove the vault, select Obsidian's folder, accept the share again. The notice offers the folder picker only while nothing syncs in the selected folder. While that finding stands, the automatic pass accepts no share: it parks, and an explicit accept goes through (the pattern of 007). "Keep It This Way" records the choice per vault, or per selected folder for as long as vaults sync there; removing the vault forgets its record. A pending share shows the destination its accept would choose (`previewShareDestination`) and says so when Obsidian will not list it. A manual target (006) is consent only under the selected folder it was chosen in; under another, a directory of that name that holds files needs the merge confirmation (#54).

**Why.** Moving a synced folder is how a vault gets attached to the wrong content (003), and so is a new selected folder under vaults that still sync: it replaces the one grant they are read through, and the container-move repair then takes each of them for a folder whose storage is gone. A notice costs nothing and ends a setup that only looks finished. Without a way to put it away, an install that syncs elsewhere on purpose would read "Action Needed" for good; with nothing syncing there is nothing to keep, and the notice is the only place that leads to another folder.

**Rejected alternatives.** Reporting every folder that syncs into the selected folder: a whole-directory sync whose shared folder contains the vaults looks the same by path and is shown by Obsidian. Reporting when a `.obsidian/` lies next to vault subfolders: 014 found that a stray one is common there, so a vault collapsed next to other vaults stays unreported. Offering the folder picker while vaults sync, with "remove first" as advice only. A critical issue or a pause: nothing is being damaged. Moving the vault for the user: 002. Telling the user to delete the earlier copy once the vault is "up to date": that status says the iPhone needs nothing from its peers, not that a peer has what was changed on it.
