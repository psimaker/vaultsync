# 050 — The tray asks through the desktop's own dialogs; the agent says which flag it needs

**Context.** M4 step 2 (#176, decision 048): `vaultsync-tray` on `fyne.io/systray`, which draws a status icon and a menu and nothing else — no text field, no list, no button. Pairing from the menu needs three answers from the person: the code, which vault, and the consent for a folder that already holds files. The agent's socket (decision 049) runs the flag flow and refuses with the flag it still needs; until now that flag was only in the refusal's words.

**Decision.** (1) The tray asks through what the desktop already has: AppleScript's dialogs via `osascript` on a Mac, `zenity` on Linux — each text passed as data (a quoted AppleScript literal, one argument), never through a shell; a Linux without `zenity` gets a Pair item that says to use `vaultsync pair` in a terminal. (2) A refusal that asks for a flag carries it as `needs` (`code`, `hub`, `vault`, `create`, `yes`) in the socket's answer (`refuseNeeding` in pair.go), and the tray acts on `needs` alone — never on the refusal's words. Each flag is asked for once per conversation; the consent dialog shows the agent's own consent text (`pairResponse.consent`: the terminal's lines, sync-plugin warnings included), and `yes` goes out only after the button, for the request the refusal was about. A vault chosen on this computer goes out as `--create`; the agent refuses `--create` for a name the Hub already has (for every client — it never turns `--create` into a download), unless the vault is already set up on this computer, which is how a repeated setup finds its own vault (#228). (3) The tray's menu lines are the agent's words; a remedy that names a terminal command is cut off the line and kept in the tooltip, because the menu has its own item for it. (4) The tray never touches the engine, holds one `tray.lock` per user in VaultSync's folder (listed in `uninstall --remove-data`'s inventory), and shares the peer-uid check with the agent through `desktop/internal/peer`.

**Why.** No GUI toolkit for three dialogs, and the person sees the dialogs they know. A structured `needs` keeps the tray honest when a refusal's wording changes, and keeps consent a decision of the person, not of a string match. One conversation per code, no session in the agent (049).

**Rejected alternatives.** Parsing the refusal text for `--yes`/`--vault` (a reworded refusal would silently break pairing, or worse, pass `yes`). A folder picker for a Hub vault's destination (`~/Vaults/<name>` is the terminal's default; the terminal takes any folder). Handing pairing to a terminal window from the menu (no reliable way to open one on Linux; the socket's pairing exists for this). Shipping icon files (five shapes drawn at start are smaller than one PNG and never stale).
