# 055 — The Linux dialogs: each text written for what its dialog reads, and a consent only a row can give

**Context.** Decision 050 asked through `zenity` on Linux and sent everyone without it to a terminal (#249). Its `--entry` text was escaped for a markup that dialog does not read, so `R&D` showed as `R&amp;D`. Tried with the real programs on zenity 3.42, 3.44, 4.0.1, 4.1.90 and kdialog 21.12, 22.12, 23.08, 25.04, which all behave alike.

**Decision.** (1) On Linux the tray asks through `zenity`, else `kdialog`; zenity stays first, so nobody's dialogs change. (2) Each text is written for its dialog. zenity `--entry`: no markup, `_` and `\` doubled. zenity `--list --text`: Pango escapes, `\` doubled. zenity `--question`/`--info` with `--no-markup`, and the rows of any list: as written. kdialog: everything as rich text with all of it escaped, `\` doubled, and in `--inputbox` `&` doubled once more. (3) kdialog's consent is a `--menu` with Cancel as the first row; only the consent row's tag on stdout from a run that ended well is a yes. (4) A list starts with a row that chooses nothing; Continue on it shows the list again, three times at most, and then a message says that nothing was chosen. (5) A row shows no number. What is read back is a hidden tag made of a character no keyboard types (U+001F), in zenity's second column, the row's words being the first. (6) A row's words that begin with `-` get a space before them. (7) A text is broken at 72 columns, except in kdialog's message box, which wraps its own. (8) A status that reads as a cancel — zenity's 1, kdialog's 1 and 2 — is one only without the toolkit's own line that it found no display: GTK 3's `cannot open display` and GTK 4's `Failed to open display`, each behind GLib's head, and Qt's `qt.qpa.xcb: could not connect to display`. A dialog program's failure is said on one line, cleaned as a Hub's error text is (062): an escape sequence goes whole, white space that breaks a line is one space, and what hides text goes. Where that line is there, it is said alone, with the display's name, which is left out rather than cut when it is too long. Otherwise what the program wrote, without Qt's four lines about a locale that is not UTF-8, at most 200 characters (#291).

**Why.** Names come from the Hub and the network, and a consent must show what it is about: kdialog reads anything that looks like markup, so `<!--` in a folder's name hid the rest of the question. Return must neither consent nor choose: zenity 4 and kdialog open a list with its first row selected. A number invites typing it, and zenity 4 filters on a typed key and selects the first row holding it; the last row of defence is that the selection is in view. What is typed must find only words in view: zenity 3 looks in the first column alone, where a typed address stopped at the row tagged `1)`, and zenity 4.1 in the hidden column too, where a typed 2 chose the row tagged `2)`. Both programs read an argument that begins with `-` as an option of their own: a vault called `-archive` kept the list from opening, and a name can spell an option that is taken, `--gtk-module=` among them. Only positive evidence is a yes, since a status can also mean a failure. A long line made a window wider than the screen, its buttons out of reach. Without a display zenity exits with 1, as a cancel does, so Pair a Vault… did nothing and said nothing; GTK's line is the only thing that tells the two apart, and a window that was shown has a display. kdialog aborts without one, and Qt writes five to eleven lines, the one that names the display first, or fifth behind its warning about a locale that is not UTF-8; the menu shows the failure as its notice, on one line. That its 1 and 2 follow zenity's rule costs nothing, since a window that was shown has a display, and a build that exits with 1 instead of aborting is not read as a cancel. Qt's locale warning names no cause and is 247 characters on one line: cut at 200, it would be all a failure says. Measured with zenity 3.42.1, 3.44.0, 4.0.1, 4.1.90 and 4.2.2 and kdialog 21.12.3, 22.12.3, 23.08.5 (Qt 5.15), 25.04.0 (Qt 6.8) and 26.08.3 (Qt 6.12), each with no display, with one named that is not there, and cancelled with Escape on one.

**Rejected alternatives.** `kdialog --warningyesno`: Return is yes, with no way to change the default. The same with swapped labels: its "no" status 1 would be the consent, and a bad option exits with 1. `--warningcontinuecancel`: Return continues. `--geometry` for a wider window: the dialog did not show in the screenshots with it. zenity's `--radiolist`, where only a marked row counts: Space marks nothing, and on zenity 4 the keyboard cannot mark a row at all. kdialog first on KDE: changes the dialogs of people who have both, for no gain. `--` before the rows: kdialog takes it, zenity lists it as a cell. A tag a keyboard can type, or the tag in the first column: see Why. No display in the environment as the sign of one missing: a `DISPLAY` that names a display with nothing behind it fails the same way (measured), and Wayland's library connects to `wayland-0` when `WAYLAND_DISPLAY` is not set (its documented default). Anything on stderr with status 1 as a failure: zenity 4 writes the graphics stack's warnings, and that it could not reach a session bus, beside a window that was shown and cancelled. The first 200 characters of what was written: in a locale that is not UTF-8 Qt's line about the display, or any other cause, comes after the 247 characters of its locale warning.
