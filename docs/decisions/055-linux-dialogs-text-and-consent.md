# 055 — The Linux dialogs: each text written for what its dialog reads, and a consent only a row can give

**Context.** Decision 050 asked through `zenity` on Linux and sent everyone without it to a terminal (#249). Its `--entry` text was escaped for a markup that dialog does not read, so `R&D` showed as `R&amp;D`. Tried with the real programs on zenity 3.42, 3.44, 4.0.1, 4.1.90 and kdialog 21.12, 22.12, 23.08, 25.04, which all behave alike.

**Decision.** (1) On Linux the tray asks through `zenity`, else `kdialog`; zenity stays first, so nobody's dialogs change. (2) Each text is written for its dialog. zenity `--entry`: no markup, `_` and `\` doubled. zenity `--list --text`: Pango escapes, `\` doubled. zenity `--question`/`--info` with `--no-markup`, and the rows of any list: as written. kdialog: everything as rich text with all of it escaped, `\` doubled, and in `--inputbox` `&` doubled once more. (3) kdialog's consent is a `--menu` with Cancel as the first row; only the consent row's tag on stdout from a run that ended well is a yes. (4) A list starts with a row that chooses nothing; Continue on it shows the list again, three times at most, and then a message says that nothing was chosen. (5) A row shows no number. What is read back is a hidden tag made of a character no keyboard types (U+001F), in zenity's second column, the row's words being the first. (6) A row's words that begin with `-` get a space before them. (7) A text is broken at 72 columns, except in kdialog's message box, which wraps its own.

**Why.** Names come from the Hub and the network, and a consent must show what it is about: kdialog reads anything that looks like markup, so `<!--` in a folder's name hid the rest of the question. Return must neither consent nor choose: zenity 4 and kdialog open a list with its first row selected. A number invites typing it, and zenity 4 filters on a typed key and selects the first row holding it; the last row of defence is that the selection is in view. What is typed must find only words in view: zenity 3 looks in the first column alone, where a typed address stopped at the row tagged `1)`, and zenity 4.1 in the hidden column too, where a typed 2 chose the row tagged `2)`. Both programs read an argument that begins with `-` as an option of their own: a vault called `-archive` kept the list from opening, and a name can spell an option that is taken, `--gtk-module=` among them. Only positive evidence is a yes, since a status can also mean a failure. A long line made a window wider than the screen, its buttons out of reach.

**Rejected alternatives.** `kdialog --warningyesno`: Return is yes, with no way to change the default. The same with swapped labels: its "no" status 1 would be the consent, and a bad option exits with 1. `--warningcontinuecancel`: Return continues. `--geometry` for a wider window: the dialog did not show in the screenshots with it. zenity's `--radiolist`, where only a marked row counts: Space marks nothing, and on zenity 4 the keyboard cannot mark a row at all. kdialog first on KDE: changes the dialogs of people who have both, for no gain. `--` before the rows: kdialog takes it, zenity lists it as a cell. A tag a keyboard can type, or the tag in the first column: see Why.
